# 启动调度、桌面清理与游戏模式

状态：设计契约。内核提供无头能力与门禁；桌面宿主负责真正接管开机启动、进程调度和界面清理。未接入前，不应在安装器里宣称这些行为已经生效。

适用对象：用户、桌面 / 前端开发者、运维。核心原则只有四条：

1. **默认不接管 OS 调度。** 不说“开机就掌控系统”；只在应用层调度自己的任务。
2. **启动必须可关闭。** 用户可以不开机启动、可以临时退出游戏模式、可以整体关闭清理功能。
3. **删除必须可回退。** 只处理可重建的启动项、快捷方式、缓存和可选扩展；不碰用户文件、系统组件和安全组件。
4. **依赖不完整就 fail-closed。** 扩展坞或插件面板缺依赖时整组不打开，而不是打开一个半残界面。

## 1. 启动档位

| 档位 | 开机启动 | 后台任务 | 清理 | 适用场景 |
| --- | --- | --- | --- | --- |
| `off` | 否 | 仅用户打开后运行 | 不执行 | 默认；服务器、CI、临时使用 |
| `balanced` | 可选，首次安装需明确询问 | 前台优先，空闲时做索引 / 更新检查 | 仅 dry-run，用户确认后执行 | 日常开发 |
| `game` | 不新增开机项 | 暂停非必要任务，保留当前 agent turn | 暂停可选扩展与动画，不删除 | 游戏 / 演示 / 低干扰 |

无论哪个档位，安全更新、权限审批、崩溃恢复、日志落盘都不能被静默关闭。`off` 只表示不主动接管，不表示内核停止工作。

配置优先级：命令行 > 环境变量 > 项目配置 > 用户配置 > 安装默认值。示例：

```json
{
  "startup": {
    "mode": "balanced",
    "on_boot": false,
    "restore_on_exit": true,
    "cleanup_dry_run_first": true
  },
  "game_mode": {
    "enabled": false,
    "keep": ["security", "system", "dev", "active_agent"],
    "pause": ["indexing", "update_check", "telemetry", "ui_animation", "optional_extensions"]
  }
}
```

外部关闭方式至少要有三种，且互相等价：

```text
TRIT_DESKTOP_MODE=off
trit-desktop --startup-mode off
桌面设置 -> 启动与性能 -> 关闭开机调度
```

## 2. 应用层调度，不改 OS 优先级

“掌控调度”指宿主自己的任务队列，不是调用 `SetPriorityClass`、实时优先级、CPU 亲和性或修改系统服务。默认禁止这些 OS 级操作；将来即使提供，也必须是单独的高级开关，并有退出恢复。

| 优先级 | 任务 | 约束 |
| --- | --- | --- |
| P0 | 权限审批、安全告警、崩溃恢复、用户输入 | 不得排队等待后台任务 |
| P1 | 当前 agent turn、工具调用、检查点 | 有界并发；写工具串行化 |
| P2 | 前台 UI 渲染、文件树、会话加载 | 不因后台索引卡住 |
| P3 | 代码索引、缓存预热、模型列表刷新 | 仅在空闲 / 前台不忙时运行 |
| P4 | 更新检查、遥测、日志轮转 | 可暂停、可完全关闭 |

必须实现的背压：

- 每个队列有最大长度；满了拒绝或合并，不无限堆积。
- 后台任务可取消；用户切回前台时，P3/P4 让出资源。
- 不因“空闲”就启动重扫描；有最小间隔和抖动。
- 当前 turn 有未完成工具调用时，不做会改变工作区的后台维护。
- 进程退出前等待 P0/P1 落盘，P3/P4 直接取消。

## 3. 桌面清理的分类

清理不是“看到不认识的都删”。先分类，再决定动作：

| 类别 | 例子 | 允许动作 |
| --- | --- | --- |
| 系统 / 安全 | 杀毒、系统更新、驱动、证书、防火墙 | 永不处理 |
| 开发组件 | 编译器、Git / 其他 SCM、shell、本地 MCP、调试器 | 游戏模式也保留；不自动卸载 |
| 用户资产 | 项目文件、会话记录、模型缓存、密钥 | 不清理；由用户显式管理 |
| 可选扩展 | 未启用的插件、示例扩展、非必要集成 | 可暂停 / 隐藏；不删除文件 |
| 冗余入口 | 重复快捷方式、失效开机项、临时缓存 | 可删除 / 禁用，但必须先 dry-run 并列清单 |

执行规则：

1. 首次清理只做 dry-run，输出“将处理什么、为什么、如何恢复”。
2. 用户确认后写入可逆清单：原路径、原状态、备份位置、操作时间、操作者。
3. 只处理应用自己的启动项、快捷方式、缓存和可选扩展；不遍历用户目录做“垃圾扫描”。
4. 任何一项无法证明可恢复，就不执行。
5. 清理失败立即停止，不回滚已成功的系统级操作（本来也不该有）；应用级操作按清单逆序恢复。
6. 退出游戏模式或重启后，按清单恢复被暂停的扩展和启动项；恢复失败要显式告警，不静默当作成功。

## 4. 游戏模式

游戏模式是“降低干扰”，不是“把系统掏空”。

进入时：

- 暂停 P3/P4 后台任务：索引、更新检查、遥测、非必要日志上传。
- 暂停可选扩展和非关键面板；保留安全、系统、开发组件和当前 agent turn。
- 关闭非必要动画、托盘提示、自动弹窗；权限审批与安全告警仍然显示。
- 不新增开机项，不修改系统服务，不结束非本应用的进程。
- 如果用户正在运行长任务，先询问“暂停 / 继续 / 退出游戏模式”，不直接杀掉。

退出时：

- 按启动前快照恢复扩展、面板、动画和后台任务。
- 恢复过程有超时；超时项标记为“未恢复”，下次启动重试，不阻塞退出。
- 崩溃后下次启动检测“游戏模式未正常退出”，先恢复再进入普通模式。

游戏模式可以被外部关闭：设置页、托盘、命令行、配置文件都算数。关闭后不保留“半游戏模式”状态。

## 5. 扩展坞 / 插件面板 fail-closed

扩展坞是一个能力组，不是一堆独立按钮。只要组内任一必需能力被锁住：

- 整组 `available = false`，`visible = false`，前端不打开空壳面板。
- 诊断信息写到开发者日志与 `GateReport.notices`，不向普通用户弹一串内部错误。
- 用户看到的文案只能是“该功能暂不可用”，不能展示内核未确认的按钮。
- 依赖恢复后，下一次能力协商自动解锁；不需要重启内核，但前端要重新取一次门禁结果。

能力门禁的字段和状态转移见 [FRONTEND-CONTRACT.md](FRONTEND-CONTRACT.md)。

## 6. 验收清单

启动 / 清理 / 游戏模式至少覆盖：

- `off` 档位不创建开机项，不启动后台扫描。
- `balanced` 首次清理必须 dry-run；取消后无副作用。
- 清理清单能恢复被禁用的启动项和扩展。
- 游戏模式进入 / 退出各一次后，扩展与后台任务状态与进入前一致。
- 模拟崩溃后重启，能识别未正常退出的游戏模式并恢复。
- 扩展坞缺一个依赖时整组隐藏，诊断日志含 owner 和原因。
- P0 审批在游戏模式下仍能弹出；P3 索引不能阻塞 P0。
- 所有外部关闭方式等价，且不会在下次启动自动打开。

## 7. 非目标

- 不做系统级实时优先级、CPU 绑核、注册表深度清理。
- 不结束非本应用进程，不卸载系统 / 安全 / 开发组件。
- 不把“清理”做成删除用户文件的入口。
- 不在没有 dry-run 和恢复清单的情况下自动执行破坏性操作。
